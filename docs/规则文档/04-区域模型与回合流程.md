## 一、对战区域模型

### 1.1 实际对战布局

双方面对面，战区沿水平方向对接，基地在各自战区后方：

```
        敌方
  ┌─────────────────────┐
  │      敌方基地区       │  ← 上限 6（角色+盖卡）
  ├─────────────────────┤
  │ 敌后卫 │ 敌侧翼×2 │ 敌先锋 │  ← 敌方战区
  ├───────┼────────┼───────┤
  │ 己先锋 │ 己侧翼×2 │ 己后卫 │  ← 己方战区
  ├─────────────────────┤
  │      己方基地区       │  ← 上限 6（角色+盖卡）
  └─────────────────────┘
        己方

场外区域（双方各有独立的一套）：
  卡组 | 冲击卡组 | 手牌 | 时间线 | 撤退区 | 虚空区
```

### 1.2 战区距离模型

战区共 6 个位置，构成一条线性路径，相邻位置距离均为 1（规则 303.2.a.4.3.1.1.1–5）：

```
己后卫 ─1─ 己侧翼 ─1─ 己先锋 ─1─ 敌先锋 ─1─ 敌侧翼 ─1─ 敌后卫
```

**完整攻击距离矩阵**（行=攻击方位置，列=目标位置）：

| 攻击方 ＼ 目标 | 敌先锋 | 敌侧翼 | 敌后卫 |
| --- | --- | --- | --- |
| **己先锋** | 1 | 2 | 3 |
| **己侧翼** | 2 | 3 | 4 |
| **己后卫** | 3 | 4 | 5 |

> **注意**：快速入门中「R-3 可达最远行」仅对**先锋位攻击方**成立。侧翼位需 R-4，后卫位需 R-5 才能打到敌方后卫。

### 1.3 R 值与可攻击目标

| R 值 | 己先锋可攻击 | 己侧翼可攻击 | 己后卫可攻击 |
| --- | --- | --- | --- |
| R-0 | 不能攻击 | 不能攻击 | 不能攻击 |
| R-1 | 敌先锋 | 无 | 无 |
| R-2 | 敌先锋、敌侧翼 | 敌先锋 | 无 |
| R-3 | 敌先锋、敌侧翼、敌后卫 | 敌先锋、敌侧翼 | 敌先锋 |
| R-4 | 全部 | 敌先锋、敌侧翼、敌后卫 | 敌先锋、敌侧翼 |
| R-5+ | 全部 | 全部 | 全部 |

### 1.4 区域操作流转

卡牌在各区域间的流转关系（箭头表示移动方向）：

| 源区域 | → 目标区域 | 操作 | 触发方式 |
| --- | --- | --- | --- |
| 手牌 | 战区/基地（正面） | 号召 / 放置 | 行动阶段、应对号召 |
| 手牌 | 基地（背面） | 基地部署 / 盖放 | 行动阶段 |
| 战区 | 战区 | 战区移动 | 效果 |
| 战区 ↔ 基地 | 战区 ↔ 基地 | 战基移动 | 行动阶段、效果 |
| 基地（正面） | 基地（背面） | 盖伏 | 效果 |
| 场上 | 撤退区 | 撤退 | 战败、效果、战力归零 |
| 手牌/卡组 | 撤退区 | 舍弃 | 效果、回合结束超限 |
| 任意 | 虚空区 | 裁剪 | 效果 |
| 卡组 | 手牌 | 抽卡 | 抽卡阶段、效果 |
| 冲击卡组 | 时间线 | 成功攻击破绽 | 战斗判定 |
| 角色 | 角色下方 | 结附 | 效果 |
| 结附卡 | 指定区域 | 解除 | 效果 |
| 任意 | 卡组 | 洗回 | 效果 |

> 区域定义、容量、公开性等基础属性见 [03-术语表与关键词速查.md](./03-术语表与关键词速查.md) 的「区域」一节，此处不重复。

## 二、回合流程状态机

### 2.1 阶段流转

每个回合严格按 6 个阶段顺序执行，不可回退：

```
回合开始 → 抽卡阶段 → 行动阶段 → 战斗阶段 → 应对阶段 → 回合结束
```

| 阶段 | 引擎枚举 | 核心动作 | 特殊限制 |
| --- | --- | --- | --- |
| 回合开始 | `TURN_START` | 触发「回合开始时」效果 | — |
| 抽卡阶段 | `DRAW` | 回合玩家抽 2 张 | — |
| 行动阶段 | `ACTION` | 部署/号召/移动/启动 | 见 2.2 |
| 战斗阶段 | `COMBAT` | 调整位置 → 按行攻击 | 先攻首回合跳过 |
| 应对阶段 | `RESPONSE` | 应对号召/应对·启动 | 见 2.4 |
| 回合结束 | `TURN_END` | ①触发结束效果 ②终止本回合效果 ③手牌弃至 9 张 | — |

### 2.2 行动阶段内部逻辑

行动阶段内 4 种行动可**任意顺序**交替进行，各自有独立计数器：

| 行动 | 计数器上限 | 引擎要点 |
| --- | --- | --- |
| 基地部署 | 1 | 盖入基地 → 抽 1 |
| 行动号召 | 3（先攻首回合 1） | 检查 Lv 规则：Lv4+ 须先撤退合计 Lv 的角色 |
| 战基移动 | 每角色 1 | 标记 `movedThisTurn`；本回合进场者不能移动 |
| 启动效果 | 无上限 | 检查效果是否有可结算内容 |

**行动阶段结束条件**：回合玩家宣布结束 → 进入战斗阶段。

### 2.3 战斗阶段内部逻辑

```
战斗阶段
  │
  ├─ 1. 调整步骤（每回合 1 次）
  │    └─ 最多 4 张战区角色互换位置（不计为移动）
  │
  └─ 2. 攻击序列
       ├─ 先锋区角色 → 单次战斗流程
       ├─ 侧翼区角色 → 单次战斗流程（两翼各有角色时可自选顺序）
       └─ 后卫区角色 → 单次战斗流程
```

**行推进规则**（v1.01 优化，303.2.a.4.8–4.10）：
- 当前行无角色 / 角色无攻击机会 / 角色不能攻击 → 跳到下一行
- 先锋 → 侧翼 → 后卫 → 阶段结束

#### 单次战斗流程（三步）

| 步骤 | 引擎枚举 | 执行内容 | 结束条件 |
| --- | --- | --- | --- |
| ① 目标步骤 | `TARGET` | 攻击者在 R 内选敌方角色或破绽 | 目标锁定 → 进入应对步骤 |
| ② 应对步骤 | `COMBAT_RESPONSE` | 敌方先 → 我方后，轮流三选一 | 双方连续不行动 |
| ③ 判定步骤 | `RESOLUTION` | 战力比较 / 攻击破绽 | 效果结算完毕 |

**应对步骤的三选一**：
1. 应对号召（双方各最多 1 次/本步骤）
2. 启动应对·启动效果
3. 不行动

**判定规则**：
- 角色 vs 角色：战力大者胜→败者撤退；相等→相杀，双方撤退
- 角色 vs 破绽：成功攻击破绽→冲击卡组顶 1 张放入时间线

**中断条件**（v1.01 新增）：攻击角色 R=0 / 离场 / 不能攻击 → 结算未结效果后战斗结束

### 2.4 应对阶段

与战斗应对步骤机制相同，但独立于战斗：

- 敌方先选 → 我方后选，轮流进行
- 三选一：① 应对号召（双方各最多 1 次/本阶段）② 应对·启动 ③ 不行动
- 双方连续不行动 → 阶段结束

### 2.5 效果触发时序

| 规则 | 说明 |
| --- | --- |
| 同一玩家多个触发 | 自选结算顺序 |
| 双方同时触发 | 回合玩家先（自选顺序），再非回合玩家 |
| 结算中再触发 | 先完成当前结算，再处理新触发 |
| 同一动作同时触发多个 | 视为同时 |

**启动型效果限制**：须存在可结算效果才能启动；含「如此做后」时须能完成前置动作才能启动。

## 三、胜负判定

### 3.1 胜利条件（满足任一）

| 条件 | 引擎判定 |
| --- | --- |
| 时间线冲击卡 ≥ 9 张 | `timeline.rushPointCount >= 9` |
| 对方卡组剩余 0 张 | `opponent.deck.size == 0` |
| 卡牌效果宣布获胜 | 效果结算触发 |

### 3.2 冲击卡获取

成功攻击对方破绽 → 从冲击卡组顶取 1 张正面朝上放入时间线。

**破绽** = 对方空置的战区位置。

**关键词对破绽判定的影响**：

| 关键词 | 影响 |
| --- | --- |
| 强袭 | 因攻击战胜对方角色时，也判定为「成功攻击破绽」 |
| 空袭 | 敌方战区有角色时，也可将该战区作为破绽攻击 |

## 四、引擎建模要点

### 4.1 卡牌状态标记

引擎需为每张场上卡维护以下状态：

| 标记 | 说明 |
| --- | --- |
| `enteredThisTurn` | 本回合放置进场；影响战基移动限制 |
| `movedThisTurn` | 本回合已战基移动；每角色每回合 1 次 |
| `attackUsed` | 本回合已攻击；连击角色有 2 次 |
| `interceptUsed` | 本回合已使用拦截；每回合 1 次 |
| `isFaceDown` | 是否为盖卡（背面朝上） |
| `attachedCards` | 结附卡列表（按结附顺序，不可改变顺序） |
| `currentPower` | 当前战力（受增减/变更效果影响） |
| `originalPower` | 原本战力（印刷值） |

### 4.2 战力变更规则（301.41）

| 变更组合 | 结果 |
| --- | --- |
| 触发/启动变更 vs 触发/启动增减 | 前者结束，后者生效 |
| 常驻变更 vs 常驻变更 | 前者结束 |
| 常驻变更 vs 触发/启动变更 | 前者结束，以常驻型变更为最终 |
| 常驻变更 + 常驻增减 | 以前者为基础叠加 |
| Lv/R/战力互相替换 | 属于变更 |

### 4.3 优先级

```
效果文本【不能】 > 效果文本【能】 > 规则文本【不能】 > 规则文本【能】
```
