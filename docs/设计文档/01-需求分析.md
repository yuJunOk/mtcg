# 需求分析

> 版本：v0.1 | 日期：2026-07-30

## 项目目标

将《超英击战》卡牌游戏规则沉淀为**可运行的在线对战后端程序**。

**游戏概述**：两名玩家各持 50 张角色卡组 + 9 张冲击卡组，通过号召部署角色、在战区攻击对手，将冲击卡放入时间线达 9 张，或抽空对方卡组即可获胜。

---

## 功能需求

### FR1：卡牌数据管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR1.1 | 角色卡 / 冲击卡 CRUD | 高 |
| FR1.2 | 卡牌查询（按颜色/等级/稀有度/名称筛选） | 高 |
| FR1.3 | 批量导入 | 中 |

### FR2：卡组构筑

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR2.1 | 创建 / 编辑 / 删除卡组（50 张主卡组 + 9 张冲击卡组） | 高 |
| FR2.2 | 卡组合法性校验（50 张 / 最多 2 色 / 同名最多 3 张 / 冲击 9 张） | 高 |
| FR2.3 | 卡牌收藏管理 | 中 |

### FR3：对战引擎（核心模块）

纯 Java 逻辑，不依赖 Spring，便于独立测试。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR3.1 | 对局初始化（洗牌 → 决定先后攻 → 发起始手牌 → Mulligan） | 高 |
| FR3.2 | 6 阶段回合流程（回合开始 → 抽卡 → 行动 → 战斗 → 应对 → 回合结束） | 高 |
| FR3.3 | 行动阶段（基地部署 / 号召 / 战基移动 / 启动效果 / 盖卡 / 结附） | 高 |
| FR3.4 | 战斗阶段（调整 → 按行攻击 → 应对 → 判定）及距离计算 | 高 |
| FR3.5 | 胜负判定（时间线 ≥9 / 抽空卡组 / 效果宣布） | 高 |
| FR3.6 | 效果系统 + 关键词能力（应对 / 拦截 / 连击 / 强袭 / 空袭 / 唯一） | 中（迭代六） |

### FR4：对战接口

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR4.1 | 创建 / 查询 / 执行操作 / 认输 对局 API | 高 |
| FR4.2 | 对局持久化（操作流水 + 回合快照），支持复盘 | 中 |
| FR4.3 | WebSocket 实时推送（未来） | 低 |

### FR5：用户系统

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR5.1 | 注册 / 登录（JWT，玩家编号 + 密码） | 高 |
| FR5.2 | 个人资料（用户名、头像） | 中 |
| FR5.3 | 对局记录 / 卡组归属 / 对局归属 | 中 |

### FR6：AI 与智能辅助

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR6.1 | AI 对战（局面评估 → 策略决策 → 应对 → 难度分级） | 中（迭代七） |
| FR6.2-4 | 卡组构筑辅助 / 对局分析 / 规则问答（未来） | 低 |

### FR7：权限管理（RBAC）

角色：玩家 / 卡牌管理员 / 系统管理员 / AI玩家。玩家仅操作自己的资源，管理员按角色授权。

### FR8：系统管理

用户管理 / 系统配置 / 操作日志（迭代九）。

### FR9：排位系统

段位（青铜→宗师）/ 排位匹配 / 排行榜 / 赛季（迭代八）。

## 非功能需求

| 需求 | 说明 |
| --- | --- |
| 引擎独立性 | `engine` 包纯 POJO，可独立单元测试 |
| 分层规范 | Controller → Service → Manager → DAO |
| 规则可追溯 | 代码注释标注规则条款编号（如 `// 303.2.a.4.3.1`） |
| 通信解耦 | 引擎与通信方式（REST/WebSocket）解耦 |
| 安全性 | BCrypt 密码 / JWT 过期 / 参数化 SQL / 输入校验 |
| 性能 | 卡牌查询 < 200ms，对局操作 < 100ms，支持 100 并发对局 |

## 迭代规划

```
阶段一（先能管） ──→ 阶段二（先能玩） ──→ 阶段三（再完善）
   迭代一：用户系统      迭代三：卡组构筑          迭代七：AI对战
   迭代二：卡牌/产品     迭代四~六：引擎核心       迭代九：排位系统
                            迭代七：对战API           迭代十：系统管理
```

| 迭代 | 范围 | 交付标准 |
| --- | --- | --- |
| **迭代一** ✅ | 用户系统 + JWT + RBAC + 用户管理 CRUD | 管理员能登录后台，能管用户账号 |
| **迭代二** | 卡牌与产品 CRUD + 管理后台页对接 | 卡牌和产品数据能录入维护 |
| 迭代三 | 卡组构筑 + 游戏端登录 | 玩家能登录游戏端，能创建合法卡组 |
| 迭代四 | 引擎状态模型 + 回合流程 | 单元测试跑通一局完整对战的阶段流转 |
| 迭代五 | 行动与战斗处理器 | ActionDispatcher + 战斗判定 |
| 迭代六 | 效果系统 + 关键词 | 效果结算正确执行 |
| 迭代七 | 对战 API + 游戏对战页 | 两名玩家能实际打完一局 |
| 迭代七~九 | AI / 排位 / 系统管理 | 见详细设计文档 |

## 已确认决策

| 问题 | 决策 |
| --- | --- |
| 通信模式 | REST 先行，WebSocket 后续 |
| 数据库 | PostgreSQL（OLTP + JSONB + 全文检索） |
| 效果解析 | 先存文本，效果 JSON 后续再做 |
| AI 集成 | 同进程调用，启发式策略先行，后续引入 LLM |
| 前端框架 | Vue 3 + PixiJS + Electron/Capacitor，Monorepo 管理 |

详细规则见 [综合规则书 v1.01](./规则文档/02-综合规则书-v1.01.md)。
