# 迭代四：引擎状态模型与回合流程

> 目标：交付对战引擎骨架——状态模型 + 6 阶段回合流转 + 对局初始化（洗牌/发牌/Mulligan），可用单元测试独立验证。
>
> 前置依赖：迭代二卡牌数据模型（快照字段来源）；迭代三卡组结构约定（50+9）供初始化校验对齐。
>
> **强制约束**（详见详细设计 §1.3）：
> - `com.aris.mtcg.engine` **纯 POJO**：禁止 Spring / MyBatis-Flex / `common` 包依赖
> - 引擎枚举不实现 `EnumBase`；仅常量 + `label`
> - 公开方法注释标注规则条款编号（如 `// 303.2.a.2`）
> - 对局中不访问数据库；卡牌以 `CardSnapshot` 自包含

## 步骤详解

### 步骤 1：RuleConstants + 引擎枚举

**目录**：`mtcg-server/src/main/java/com/aris/mtcg/engine/`

1. 新建 `rule/RuleConstants.java`（详细设计 §6.1 常量全集）
2. 新建枚举：
   - `PhaseType`：`TURN_START → DRAW → ACTION → COMBAT → RESPONSE → TURN_END`，`next()` 在 `TURN_END` 后回到 `TURN_START`
   - `GameStatus`：`WAITING` / `IN_PROGRESS` / `FINISHED`
   - `Zone`：手牌/卡组/冲击卡组/撤退区/时间线/战区位/基地等；`isOnField()` 覆盖战区+基地（Q&A Q1）
   - `PlayerSide`：`FIRST` / `SECOND` + `opposite()`

**检验**：`mvnw.cmd compile`；确认 `engine` 包无 Spring/`common` import。

---

### 步骤 2：CardSnapshot / CardInstance

**参照**：详细设计 §2.1–§2.2

| 类 | 要点 |
| --- | --- |
| `CardSnapshot` | `final` 字段；构造入参防御性拷贝 `traits`；仅 getter |
| `CardInstance` | 持有 `CardSnapshot`；`instanceId`、`currentZone`、本回合标记（已召唤/已移动/已攻击等）、战力修正列表（可空骨架，迭代六用） |
| | `resetTurnFlags()` 供回合结束调用 |

**检验**：可用纯 Java `main`/单测构造 Snapshot→Instance，断言不可变与默认标志。

---

### 步骤 3：FieldZone / PlayerState / GameState / ActionLog

**参照**：详细设计 §2.3–§2.6

| 类 | 要点 |
| --- | --- |
| `FieldZone` | 先锋/侧翼/后卫/基地结构；`isBaseFull()`（`MAX_BASE=6`）；遍历场上角色需覆盖基地（Q&A Q7 留给迭代五） |
| `PlayerState` | `playerId`、`side`、`deck`/`rushDeck`/`hand`/`retreat`/`timeline`、`field`、回合行动计数器 |
| `GameState` | `gameId`、`status`、`turnCount`、`currentPhase`、`firstPlayer`、`activePlayer`/`inactivePlayer`、`winnerId`、`actionLogs`；`switchActivePlayer()` |
| `ActionLog` | 最小字段：序号、玩家、动作类型、描述、时间戳（本迭代可只建类） |

**约定**：卡组顶 = `deck` 列表**末尾**；卡组底 = 列表**头部**（与详细设计一致，抽卡/Mulligan 必须遵守）。

**检验**：组装空对局状态对象无 NPE。

---

### 步骤 4：PhaseHandler + 六阶段处理器

**接口**：`void onEnter(GameState state, GameEngine engine);`

| Handler | 本迭代行为 |
| --- | --- |
| `TurnStartHandler` | TODO 效果 → 直接 `advancePhase()` |
| `DrawHandler` | 主动玩家抽 `DRAW_PER_TURN`；不足则按设计检查胜负；`advancePhase()` |
| `ActionHandler` | **等待外部结束行动**（本迭代可提供 `endActionPhase(engine)` 或测试里手动 `advancePhase`）；不实现四类行动 |
| `CombatHandler` | 若 `turnCount==1 && active==first` → 跳过战斗直接推进；否则本迭代骨架推进/等待（详细设计为准） |
| `ResponseHandler` | 骨架：连续不行动后推进（测试可直接 `advancePhase`） |
| `TurnEndHandler` | 手牌 > `MAX_HAND_END_TURN` 舍弃至上限；`resetTurnFlags`；效果清理 TODO 迭代六；`switchActivePlayer`；`turnCount++`；进入下一回合 `TURN_START` |

> Action / Combat / Response 的「交互等待」实现方式以实现时与详细设计 §4.5–4.7 对齐为准：保证 **阶段顺序不可回退**，并为迭代五预留扩展点即可。

**检验**：编译通过；单测见步骤 7。

### 步骤 5：GameEngine

**参照**：详细设计 §4.1

- 构造时 `registerHandlers()` 注册 6 个 Handler
- `startGame()`：`IN_PROGRESS`、`turnCount=1`、`enterPhase(TURN_START)`
- `enterPhase` / `advancePhase` / `endGame(winnerId)`
- `getState()`

**检验**：从 `WAITING` 状态 `startGame()` 后能自动走到 `ACTION`（若 TurnStart/Draw 自动推进）。

### 步骤 6：GameInitializer

**参照**：详细设计 §5.2–§5.3

## 实现注意（易错点）

1. **列表方向**：顶=末尾、底=头部；抽卡用 `remove(size-1)`，置底用 `add(0, ...)`
2. **Mulligan 索引**：必须降序删除，避免偏移
3. **先攻首回合**：战斗跳过依据 `turnCount` + `firstPlayer`（303.2.a.4.1）
4. **效果 TODO**：TurnStart / TurnEnd 的效果结算只留注释，勿引入 `common` 异常体系；引擎内用 `IllegalArgumentException` / `IllegalStateException` 即可
5. **与迭代三校验对齐**：引擎初始化只校验张数 50/9；颜色/同名等构筑规则仍在 `DeckService`，不在引擎重复
