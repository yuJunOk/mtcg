# 卡牌素材补充指南

> **用途**：以后补充卡图 / 卡表数据时只看本文即可。  
> **相关脚本**：`scripts/官网卡表拉取`、`scripts/卡面提取`、`scripts/card_common`  
> **最后更新**：2026-08-13

---

## 1. 一句话结论

两条线产出 **同一套目录 / 命名 / 画布 / SQL 字段**，只是数据来源不同：

| 来源 | 何时用 | 脚本 | 种子 SQL |
|------|--------|------|----------|
| 官网卡表 API | 已有系列角色卡（BP/SD 等） | `scripts/官网卡表拉取/fetch_cards.py` | `sql/seed-official-cards.sql`（整包） |
| APP 截图补齐 | 官网没有的冲击卡、推广包、赛事包等 | `scripts/卡面提取/pipeline.py` | `sql/seed-cards/{产品}.sql`（按产品） |
| 统一修规格 | 任意已有 PNG | `scripts/card_common/normalize_cli.py` | — |

共享模块：

- 画布规格：`scripts/card_common/spec.py` + `normalize.py`
- 幂等 INSERT：`scripts/card_common/seed_sql.py`（两条线都用）

**最终入 UI / SQL 的卡图**一律：

```text
assets/card/faces/{产品编码}/{编号}-{罕度}.png
```

例如：`BP01/BP01-001-MR.png`、`PB01/PB01-001-PR.png`

> `assets/card/faces/`、`raw/`、`extracted/` **均不提交 Git**（已 gitignore）。  
> 最终卡图用网盘共享；本机放到 `assets/card/faces/{产品}/`，后端 `/files` 即可读到。

## 2. 统一画布规格（两边必须一致）

| 项 | 值 |
|----|----|
| 尺寸 | **1488 × 2080** |
| 格式 | RGBA PNG |
| 透明边 | **无**（仅圆角透明） |
| 圆角 | 宽 × `41/747` ≈ **82px** |

```text
去透明边 → 等比缩放并居中贴到 1488×2080 → 统一圆角
```

## 3. 目录与种子约定

```text
assets/card/
├── raw/{任意子目录}/           # 截图原图
├── extracted/{批次}/           # 截图中间结果（cards / code_badges / catalog.json）
└── faces/{产品编码}/           # ★ 最终卡图（官网拉取 + 截图补齐都写这里）

mtcg-server/src/main/resources/sql/
├── seed-official-cards.sql     # 官网整包
├── seed-cards.sql              # 截图补齐入口（\ir 引用下面分文件）
└── seed-cards/
    ├── BP01.sql
    ├── PB01.sql
    └── …

scripts/
├── card_common/                # 规格 + seed_sql（共享）
├── 官网卡表拉取/               # 流程 A
└── 卡面提取/                   # 流程 B
    ├── extract_card.py         # 单次/批量裁切
    ├── pipeline.py             # prepare → apply → sql
    └── catalogs/               # 已填写的 catalog 存档（可复用）
```

| 可提交 Git 的数据 | 说明 |
|------|------|
| `scripts/官网卡表拉取/out/cards.json` / `products.json` | 官网元数据 |
| `scripts/卡面提取/catalogs/*.json` | 截图批次 catalog（编号/字段） |
| `sql/seed-official-cards.sql` | 官网种子 |
| `sql/seed-cards.sql` + `sql/seed-cards/*.sql` | 截图补齐种子 |

> 卡图 PNG 不入库：网盘同步到本地 `assets/card/faces/` 即可。

`mtcg_card.image_path = card/faces/{产品}/{card_code}.png`

前端访问：`/files/` + `image_path`（开发环境 Vite 代理到 `/api/files/...`）。  
后端将 `/files/**` 映射到 `file.upload.base-path`（上传）与 `file.assets.base-path`（默认 `../assets`，含 `card/faces`）。

## 4. 命名规则

| 项 | 规则 | 示例 |
|----|------|------|
| `card_code` / 文件名 | `{基础编号}-{罕度}` | `BP01-150-C` |
| 罕度 | C/R/SR/GR/UR/MR/SEC/PR/ER/TR… | `SEC` |
| 系列目录 | = `product_code` | `BP01`、`PB01`、`EB01` |

同一编号多罕度 = 多条记录、多张图。

## 5. 流程 A：官网卡表（优先）

```bash
python scripts/官网卡表拉取/fetch_cards.py
python scripts/官网卡表拉取/fetch_cards.py --skip-images
python scripts/官网卡表拉取/fetch_cards.py --force-images
python scripts/官网卡表拉取/fetch_cards.py --workers 2
```

Windows Python 示例：`D:\ProgramApp\Python\python-3.13.14\python.exe`

说明：Range 分片下载、PNG 校验、自动 normalize；官网目前通常 **只有角色卡**。

详见 `scripts/官网卡表拉取/README.md`。

---

## 6. 流程 B：截图补齐（推荐用 pipeline）

### 6.1 截图

1. APP 打开卡详情全屏截图（默认标定分辨率 **1080×2354**）。
2. 放入 `assets/card/raw/{便于整理的子目录}/`。

### 6.2 prepare：裁切 + 生成 catalog 模板

```bash
python scripts/卡面提取/pipeline.py prepare assets/card/raw -o assets/card/extracted/batch1
```

产出：

- `batch1/cards/**`：1488×2080 卡面
- `batch1/code_badges/**`：右上角编号徽章（便于辨认编号/罕度）
- `batch1/catalog.json`：待填模板

### 6.3 填写 catalog.json

每张卡至少填：

```json
{
  "source": "PB-推广包/xxx.jpg",
  "base_card_no": "PB01-001",
  "rarity": "PR",
  "card_name": "「毁灭者」德拉克斯",
  "card_type": "CHARACTER",
  "level": 6,
  "color": "RED",
  "traits": "银河护卫队",
  "attack_range": 1,
  "power": 6000,
  "effect_text": "……"
}
```

冲击卡：`card_type = RUSH_POINT`，`level/traits/attack_range/power/effect_text` 可为 `null`；有宝石名可写「时间/空间/…」并填 `color`。

同 `card_code` 多张源图会自动去重（保留首条）。

参考存档：`scripts/卡面提取/catalogs/2026-08-12.json`。

### 6.4 apply：入库图 + 按产品生成 SQL

```bash
python scripts/卡面提取/pipeline.py apply assets/card/extracted/batch1/catalog.json
# 或只用存档 catalog 重生成 SQL：
python scripts/卡面提取/pipeline.py sql scripts/卡面提取/catalogs/2026-08-12.json
```

结果：

- 卡图 → `assets/card/faces/{产品}/`
- SQL → `sql/seed-cards/{产品}.sql` + 入口 `sql/seed-cards.sql`

### 6.5 仅裁切（旧入口，仍可用）

```bash
python scripts/卡面提取/extract_card.py assets/card/raw -o assets/card/extracted
```

裁切框不对时用 `--left/--top/--right/--bottom` 微调。

颜色/类型约定：`红色→RED`；`character→CHARACTER`；冲击卡 → `RUSH_POINT`。

python scripts/card_common/normalize_cli.py assets/card/faces --force

## 8. 检查清单

- [ ] 文件在 `assets/card/faces/{产品}/`
- [ ] 文件名 = `{编号}-{罕度}.png` = `card_code`
- [ ] 尺寸 1488×2080，无多余透明垫边
- [ ] 官网卡：`seed-official-cards.sql`；截图补齐：`seed-cards/*.sql`
- [ ] `image_path` 正确；前端可用 `/files/{image_path}` 打开卡图
- [ ] 卡图用网盘共享；本地已放到 `faces/`；勿提交 `raw/` / `extracted/` / `faces/`
- [ ] 截图批次 catalog 已存到 `scripts/卡面提取/catalogs/`（便于复跑）

## 9. 常见问题

| 现象 | 处理 |
|------|------|
| 官网图残缺 | 重跑 `fetch_cards.py` |
| 四周透明边 | `normalize_cli.py assets/card/faces` |
| 截图裁切偏 | `extract_card.py --left/--top/...` 或改 region 后 `pipeline prepare` |
| 官网没有某张卡 | 流程 B + catalog |
| 编号认不清 | 看 `code_badges/`，或对照 APP |
| Python 找不到 | 用本机绝对路径，见 `run_extract.bat` |
