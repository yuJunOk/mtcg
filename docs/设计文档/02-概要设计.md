# 概要设计

> 版本：v0.1 | 日期：2026-07-30

## 系统架构

```
客户端层(mtcg-client)  ──REST──►  API层  ──►  Service层  ──►  Manager层  ──►  引擎层(纯POJO)
                              │                        │
                              │                        ▼
                              ▼                   DAO层 ──►  PostgreSQL
                         Controller层
```

**分层职责**：

| 层 | 职责 | 技术 |
| --- | --- | --- |
| 客户端 | UI 渲染 + 状态管理 | Vue 3 / PixiJS / Electron / Capacitor |
| API | 请求校验 + 协议适配 | Spring Controller |
| Service | 业务编排 | Spring Service |
| Manager | AI 决策 / 缓存 / 通用能力 | Spring Component |
| 引擎 | 纯规则逻辑（回合 / 战斗 / 效果） | **纯 POJO**，不依赖 Spring |
| DAO | 持久化 | MyBatis-Flex |

## 数据库设计

**约定**：不追求三大范式，不使用数据库外键，关系完整性在应用层校验。

| `mtcg_audit_log` | 审计日志雏形（actor/action/resource） | ✅ 迭代二前置；迭代十完善 |
| `mtcg_deck` | 卡组（卡牌编号 JSON，50+9） | 🔲 迭代三 |
| `mtcg_card_collection` | 卡牌收藏 | 🔲 迭代三 |
| `mtcg_game_record` | 对局记录（action_log + turn_snapshot） | 🔲 迭代七 |

## 核心模型

### 引擎状态

```java
GameState       // 对局全局状态（gameId / 双方玩家 / 当前阶段 / 操作流水）
PlayerState     // 玩家状态（手牌 / 卡组 / 战区 / 基地 / 撤退区...）

```

## API 规范

### 路径设计原则

- **按业务领域分包**，权限通过路径前缀区分
- 公开接口：`/cards`, `/products` → 无需登录
- 用户接口：`/users` → 需登录
- 管理员接口：`/admin/*` → 需特定角色

### 统一规范

- 统一前缀：`/api/v1`
- 统一响应：`{code, message, data}`
- 鉴权：`Authorization: Bearer <token>`（注册/登录除外）
- 分页：QueryDTO 使用 `pageNum` / `pageSize`（默认 1 / 10）
- HTTP 方法：只使用 GET 和 POST

### Controller 包结构

```
controller/
├── auth/AuthController              → /auth/*
├── user/UserController              → /users/*
├── card/
│   ├── CardController               → /cards/* (公开)
│   ├── AdminCardController          → /admin/cards/* (管理员)
│   └── CardFeatureController        → /cards/features/* (管理员)
├── product/
│   ├── ProductController            → /products/* (公开；含 /{productCode}/cards)
│   └── AdminProductController       → /admin/products/* (管理员)
├── admin/
│   ├── AdminUserController          → /admin/users/*
│   └── AdminDashboardController     → /admin/dashboard/*
└── system/HealthController          → /health/* (公开)
```

### 主要接口

| 模块 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| 认证 | POST /auth/register, /login, /refresh, /logout | 公开/登录 | 注册 / 登录 / 刷新 / 登出 |
| 用户 | GET/POST /users/me* | 登录用户 | 个人资料 / 改密 |
| 卡牌查询 | GET /cards, GET /cards/{id} | 公开 | 卡牌列表/详情 |
| 卡牌管理 | GET/POST /admin/cards/* | CARD_ADMIN+ | 卡牌增删改 + 上传 |
| 卡牌特征 | GET/POST /cards/features/* | CARD_ADMIN+ | 特征 CRUD + 卡牌关联 |
| 产品查询 | GET /products, GET /products/{id} | 公开 | 产品列表/详情 |
| 按产品查卡 | GET /products/{productCode}/cards | 公开 | 产品下卡牌分页 |
| 产品管理 | GET/POST /admin/products/* | CARD_ADMIN+ | 产品增删改 |
| 用户管理 | GET/POST /admin/users/* | SYS_ADMIN | 用户管理 |
| 仪表盘 | GET /admin/dashboard/stats | 管理员 | 统计数据 |
| 卡组 | GET/POST /decks/* | 登录用户 | 卡组 CRUD + 校验（迭代三） |
| 对战 | POST /games, POST /games/{id}/actions | 登录用户 | 创建对局 / 执行操作（迭代七） |
| 排位 | GET/POST /rank/* | 登录用户 | 段位 / 匹配 / 排行榜（迭代九） |
| AI | POST /ai/games | 登录用户 | AI 对局（迭代八） |

## 引擎解耦要点

- `GameEngine` 是纯 POJO，无 `@Component`/`@Service`，通过 `new` 创建
- `GameService` 负责生命周期管理和持久化，不含规则逻辑
- 对局中引擎不查 DB，卡牌数据在初始化时一次性加载为快照
- 可独立单元测试，无需启动 Spring 容器

## 关键决策

| 问题 | 决策 | 理由 |
| --- | --- | --- |
| 卡组存储 | 存卡牌编号 JSON 数组 | 固定规模，稳定可读，导入导出友好 |
| 对局持久化 | 操作流水 + 回合快照 | 崩溃恢复 = 快照 + 重放；复盘 = 逐条回放 |
| AI 集成 | 同进程调用 | 当前启发式计算量小，直接调用最自然 |
