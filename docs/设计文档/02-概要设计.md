# 概要设计

> 版本：v0.1 | 日期：2026-07-30

## 系统架构

```
客户端层(mtcg-client)  ──REST──►  API层  ──►  Service层  ──►  Manager层  ──►  引擎层(纯POJO)
                              │                        │
                              │                        ▼
                              ▼                   DAO层 ──►  PostgreSQL
                         Controller层
```

**分层职责**：

| 层 | 职责 | 技术 |
| --- | --- | --- |
| 客户端 | UI 渲染 + 状态管理 | Vue 3 / PixiJS / Electron / Capacitor |
| API | 请求校验 + 协议适配 | Spring Controller |
| Service | 业务编排 | Spring Service |
| Manager | AI 决策 / 缓存 / 通用能力 | Spring Component |
| 引擎 | 纯规则逻辑（回合 / 战斗 / 效果） | **纯 POJO**，不依赖 Spring |
| DAO | 持久化 | MyBatis-Flex |

## 数据库设计

**约定**：不追求三大范式，不使用数据库外键，关系完整性在应用层校验。

### 核心表

| 表 | 说明 |
| --- | --- |
| `mtcg_user` | 用户（role: PLAYER/CARD_ADMIN/SYS_ADMIN/AI，BCrypt 密码） |
| `mtcg_card` | 卡牌（统一表，card_type 区分角色卡/冲击卡） |
| `mtcg_product` | 卡包（product_code 唯一标识） |
| `mtcg_deck` | 卡组（存卡牌编号 JSON 数组，50+9 固定规模） |
| `mtcg_game_record` | 对局记录（action_log 操作流水 + turn_snapshot 回合快照） |
| `mtcg_rank_info` | 排位（按 season_id 赛季隔离） |
| `mtcg_card_collection` | 卡牌收藏 |
| `mtcg_notification` | 消息通知 |

## 核心模型

### 引擎状态

```java
GameState       // 对局全局状态（gameId / 双方玩家 / 当前阶段 / 操作流水）
PlayerState     // 玩家状态（手牌 / 卡组 / 战区 / 基地 / 撤退区...）
CardInstance    // 卡牌实例（快照字段 + 运行时状态，DB 只在初始化时加载一次）
FieldZone      // 场上区域（先锋区×1 / 侧翼区×2 / 后卫区×1 / 基地区×6）
```

### 关键枚举

```
Color         // RED / YELLOW / BLUE / GREEN / ORANGE / PURPLE
PhaseType     // TURN_START / DRAW / ACTION / COMBAT / RESPONSE / TURN_END
Zone          // VANGUARD / FLANK / REARGUARD / BASE / DECK / HAND / TIMELINE...
EffectType    // TRIGGER / CONTINUOUS / ACTIVATED / RESPONSE_ACTIVATED
Keyword       // RESPONSE / INTERCEPT / COMBO / ASSAULT / AIR_STRIKE / UNIQUE
ActionType    // MULLIGAN / SUMMON / ATTACK / INTERCEPT / END_PHASE...
```

### 距离计算

```
己后卫 ─ 己侧翼 ─ 己先锋 ─ 敌先锋 ─ 敌侧翼 ─ 敌后卫
  0        1        2        3        4        5
距离 = |位置索引差|
```

## API 规范

- 统一前缀：`/api/v1`
- 统一响应：`{code, message, data}`
- 鉴权：`Authorization: Bearer <token>`（注册/登录除外）
- 分页：`?page=1&size=20`

**主要接口**：

| 模块 | 路径 | 说明 |
| --- | --- | --- |
| 认证 | POST /auth/register, /auth/login | 注册 / 登录 |
| 用户 | GET/PUT /users/me | 个人资料 |
| 卡牌 | GET/POST/PUT/DELETE /cards | 卡牌 CRUD + 批量导入 |
| 产品 | GET/POST/PUT/DELETE /products | 产品 CRUD |
| 卡组 | GET/POST/PUT/DELETE /decks | 卡组 CRUD + 校验 |
| 对战 | POST /games, POST /games/{id}/actions | 创建对局 / 执行操作 |
| 排位 | GET/POST /rank/* | 段位 / 匹配 / 排行榜 |
| AI | POST /ai/games | AI 对局 |

## 引擎解耦要点

- `GameEngine` 是纯 POJO，无 `@Component`/`@Service`，通过 `new` 创建
- `GameService` 负责生命周期管理和持久化，不含规则逻辑
- 对局中引擎不查 DB，卡牌数据在初始化时一次性加载为快照
- 可独立单元测试，无需启动 Spring 容器

## 关键决策

| 问题 | 决策 | 理由 |
| --- | --- | --- |
| 卡组存储 | 存卡牌编号 JSON 数组 | 固定规模，稳定可读，导入导出友好 |
| 对局持久化 | 操作流水 + 回合快照 | 崩溃恢复 = 快照 + 重放；复盘 = 逐条回放 |
| AI 集成 | 同进程调用 | 当前启发式计算量小，直接调用最自然 |
