# 迭代六：效果系统与关键词能力

> 目标：在迭代四/五之上交付效果结算骨架与 6 个关键词能力，使「启动效果 / 触发队列 / 常驻重算 / 战力修改 / 关键词挂接」可跑通；效果文本结构化解析仅留空壳。
>
> 前置依赖：迭代五 `GameEngine.dispatch` / `ActionDispatcher` / `ActivateEffectHandler`（骨架）/ `BattleResolver` / `WinChecker` / `DistanceCalculator` / `CombatContext` 等已就绪。见 [17-实现步骤 §迭代六前置接口](./17-实现步骤-迭代五-引擎行动与战斗.md)。
>
> **强制约束**（详见详细设计 §1.3）：
> - `engine.effect` / `engine.keyword` 纯 POJO：禁止 Spring / MyBatis / `common` 依赖
> - 注释标注规则条款编号（如 `// 304.1`）
> - Effect 定义不可变；运行时变更进 `PowerModifier` / `CardInstance` 状态
> - `EffectParser` 本迭代仅空壳；`effectJson` 可空不报错
> - **不**在本迭代实现完整效果 DSL 解析与全量卡牌效果脚本

### 与现有代码的命名冲突（必读）

设计稿 `engine.keyword` 下的类名与迭代四/五已有类冲突，实现时**必须改名**：

| 设计稿类名 | 已有类 | 本迭代建议类名 |
| --- | --- | --- |
| `keyword.ResponseHandler` | `phase.ResponseHandler`（应对**阶段**） | `ResponseKeywordHandler` |
| `keyword.InterceptHandler` | `action.handler.InterceptHandler`（拦截**操作**） | `InterceptKeywordHandler` |

其余关键词处理器建议统一后缀：`ComboKeywordHandler` / `AssaultKeywordHandler` / `AirStrikeKeywordHandler` / `UniqueKeywordHandler`，避免与 action Handler 混淆。

### 与现有模型的 as-built 对齐

| 设计稿写法 | 现有实现 | 处理 |
| --- | --- | --- |
| `import ...engine.model.Zone` | `Zone` 在 `engine.enums` | 改用 `com.aris.mtcg.engine.enums.Zone` |
| `CardInstance.getKeywords()` | 尚无；迭代五用 `effectText` 含 `【唯一】` 等轻量判定 | **本迭代**在 `CardInstance`（或快照/效果列表）上补 `Set<Keyword>` / `List<Effect>`；替换 `ActionSupport.hasXxxKeyword` |
| `ActivateEffectHandler` 骨架 | 仅校验+记流水 | 填实：委托 `EffectResolver.activate` |
| `BattleResolver` 强袭/连击 | `ActionSupport.hasAssaultKeyword` / `hasComboKeyword` | 改为查 `Keyword` 枚举 + KeywordHandler |
| `SummonHandler` 唯一 | `effectText` 含 `【唯一】` | 改为 `UniqueKeywordHandler` / `card.getKeywords().contains(UNIQUE)` |
| 空袭破绽 | 迭代五 `assertVulnerable` 要求空置 | 有 `AIR_STRIKE` 时允许有角色的战区破绽位（305.5） |
| `phase.ResponseHandler` / `TurnStart` / `TurnEnd` | 框架或直接推进 | 挂接 `fireTriggers`（回合开始/结束等）；本迭代可先接关键事件 |

## 步骤详解

### 步骤 1：效果基础模型

**目录**：`engine/effect/`

1. `EffectType`：4 常量 + 注释（201.10.d–f）
2. `Effect`：不可变（或仅构造后只读）；`type` / `effectiveZone` / `requirement` / `text` / `condition` / `action` / `keywords`
3. `EffectContext`：`source`、`gameState`、目标列表、可选控制器等
4. `TriggerType` / `TriggerEvent`：至少覆盖 ENTERS_ZONE、TURN_START、TURN_END、ATTACK_DECLARE 等本迭代要用的事件（可按设计稿全量枚举）
5. `TriggeredEffect` / `TriggerBatch`：批次内排序钩子（默认入队顺序；预留玩家自选）

**检验**：`mvnw.cmd compile`；无 Spring/`common`。

---

### 步骤 2：PowerModifier + Stack

**参照**：详细设计 §5、Q&A Q2

| 要点 | 说明 |
| --- | --- |
| `PowerModifier` | Attribute（POWER/RANGE…）、Category、Duration（THIS_TURN / WHILE_IN_ZONE…） |
| `PowerModifierStack` | `add` / `compute` / `removeExpiredThisTurn`；结果下限 0（301.8） |
| 归零撤退 | `compute` 后调用方若 POWER==0 → 撤退（301.16.b）；**不**把撤退写死在 Stack 内亦可，但须有统一入口 |

**检验**：单测叠加、本回合到期清理、归零。

---

### 步骤 3：优先级

**参照**：详细设计 §4

- `PriorityLevel` + `PriorityResolver`
- 供 `TriggerBatch` 排序与启动冲突裁定使用
- 本迭代可先实现规则表中的基础层级，复杂嵌套留扩展点

**检验**：同批次多效果按优先级排序的单测（可用手造 Effect）。

---

### 步骤 4：EffectParser 空壳 + EffectResolver

**参照**：详细设计 §3、§7、Q&A Q3–Q6

| 能力 | 要点 |
| --- | --- |
| `NoOpEffectParser` | `effectJson`/原文 → 空 keywords 或仅从文本抽取关键词标记（可选）；不抛错 |
| `EffectResolver.fireTriggers` | 收集匹配触发；**排除自身进场触发自身**（Q4） |
| `resolveAll` / `resolveEffect` | 按 304.1 排序；对象选择基于**最新** `GameState`（Q5） |
| `reevaluateContinuous` | 进场时**先于**触发队列（Q6） |
| `activate` | 启动型 / 应对·启动时点校验（304.2）；结附卡仍可启动（Q3） |
| 可选标记 | 文本含「可以」→ optional；玩家放弃则跳过（可先默认必发策略 + 预留接口） |

**检验**：`NoOp` 不炸；手造 TRIGGER/CONTINUOUS/ACTIVATED 最小路径单测。

---

### 步骤 5：Keyword 体系

**参照**：详细设计 §6（类名用本文「建议类名」）

1. `Keyword` 枚举：RESPONSE、INTERCEPT、COMBO、ASSAULT、AIR_STRIKE、UNIQUE
2. `KeywordHandler`：`getKeyword` / `canApply` / `apply`（或设计稿等价方法）
3. `KeywordHandlerRegistry`：构造时注册 6 个实现
4. 各 Handler 行为对齐 305.1–305.6；与迭代五已有操作 Handler **分工**：
   - action 层：玩家指令校验与状态改写入口
   - keyword 层：规则能力判定与战斗/号召钩子

**检验**：每个关键词至少 1 个单测（可与步骤 8 合并）。

---

### 步骤 6：挂接既有流程

| 挂接点 | 动作 |
| --- | --- |
| `ActivateEffectHandler` | `validate` 可启动时点 + 有效效果；`execute` → `EffectResolver.activate` |
| `BattleResolver` | 战胜 + ASSAULT → 冲击进时间线；删除/替换 `hasAssaultKeyword` 文本探测 |
| `AttackSequenceHandler` | COMBO → 攻击上限 2；AIR_STRIKE → 破绽校验放宽 |
| `SummonHandler` | UNIQUE → 同名在场禁止；走 `card.getKeywords()` |
| `TurnEndHandler` | `removeExpiredThisTurn` + 可选 TURN_END 触发 |
| `TurnStartHandler` | TURN_START 触发（可与常驻重算顺序按设计） |
| 号召/进场后 | `onCardEntersZone`：先 `reevaluateContinuous`，再 `fireTriggers(ENTERS_ZONE)`（Q6） |

**检验**：原有迭代五引擎单测仍绿；新增关键词相关用例。

## 实现注意（易错点）

1. **命名**：keyword 包 Handler 必须加 `Keyword` 后缀，勿覆盖 `phase.ResponseHandler` / `action.handler.InterceptHandler`
2. **Zone 包路径**：一律 `engine.enums.Zone`
3. **Q6 顺序**：进场 → 常驻重算 →（可能归零撤退）→ 再触发；不可颠倒
4. **Q4**：`ENTERS_ZONE` 收集时排除「事件源 == 效果源」的自身触发
5. **Q3**：结附卡不是盖卡，效果仍有效
6. **Q2**：战力 0 立即撤退；`THIS_TURN` 修改器回合末必须清
7. **Parser**：空壳即可，禁止本迭代偷偷做完整脚本引擎
8. **与迭代五兼容**：替换文本探测前保证单测等价通过
